# 安全建议

API Key 等同于可消费账户额度的密码。请按以下方式管理。

## 推荐做法

- 每个设备、服务和环境使用独立 Key。
- 为 Key 设置合理的总配额、滚动限额和有效期。
- 只在服务器端环境变量或 Secret 管理器中保存 Key。
- 定期检查用量、来源 IP、模型和异常消费。
- 人员离职、设备丢失或疑似泄露时立即轮换。
- 在日志和错误上报中统一脱敏，例如只保留末尾四位。

## 禁止做法

- 不要把 Key 提交到 GitHub、GitLab 或公开网盘。
- 不要写进网页 JavaScript、移动应用包或浏览器扩展。
- 不要在群聊、工单、截图或录屏中展示完整 Key。
- 不要通过 URL 查询参数传递 Key。
- 不要把一个无限额 Key 分发给多人长期共用。

## Git 泄露后的处理

仅从最新提交删除 Key 不够，因为它仍存在于历史记录中：

1. 立即在控制台撤销旧 Key。
2. 创建新 Key 并更新应用 Secret。
3. 检查泄露时间后的用量记录。
4. 如有必要，使用专业工具清理 Git 历史并强制更新远端。
5. 通知所有协作者重新拉取已清理的历史。

第一步永远是撤销，而不是先清理仓库。
