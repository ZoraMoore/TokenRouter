# 常见问题

## Codex 重连 5 次后断连怎么解决？

这通常表示 Codex 多次尝试重连后仍无法稳定访问网络或上游服务。若你的网络环境需要本地代理，可将下面的提示词直接发送给 Codex，让它先识别正在使用的代理端口，再写入自己的环境配置。

```text
帮我在 ~/.codex.env 写入代理信息。

请先帮我定位我本机正在使用的代理端口，然后把下面示例里的 15236 替换成实际端口：
HTTP_PROXY="http://127.0.0.1:15236"
HTTPS_PROXY="http://127.0.0.1:15236"
ALL_PROXY="http://127.0.0.1:15236"
NO_PROXY="localhost,127.0.0.1,::1"

写入完成后告诉我改了哪个文件。
```

完成后重新启动 Codex，再发起一次请求。若仍然断连，请确认本地代理正在运行、端口未被防火墙拦截，并保留错误信息和 `X-Request-ID` 以便排查。

## API 地址应该填哪个？

- OpenAI SDK、Codex、OpenAI 兼容客户端：通常是 `https://api.scienceedu.me/v1`。
- Anthropic SDK、Claude Code：`https://api.scienceedu.me`。
- Gemini CLI / 原生 SDK：`https://api.scienceedu.me`。

如果出现 `/v1/v1`，说明客户端和配置都追加了版本路径。

## 为什么模型广场有模型，但我的 Key 看不到？

`/v1/models` 返回的是当前 Key 所属分组可见的模型，不是全站所有模型。请确认创建 Key 时选择的分组，并查看该分组是否仍可用。

## 为什么返回 403 protocol_not_allowed？

该 Key 的最终分组没有开放你调用的客户端协议。比如客户端使用 Responses API，但分组只允许 Anthropic Messages。请换协议或创建绑定正确分组的 Key。

## 为什么返回 404？

可能是 URL 写错，也可能是当前分组平台不支持该能力。例如 Embeddings、图片、视频、语音并不是所有分组都提供。先测试 `/v1/models`，再核对端点与分组。

## 余额还有，为什么请求提示额度不足？

Key 可能设置了总配额、滚动限额或“指定订阅”计费模式。调用 `/v1/usage`，查看 Key 限额和 `billing` 对象。

## Key 可以在多个设备共用吗？

技术上可以，但不建议。每个设备或应用单独建 Key，泄露时更容易定点撤销，用量也更清晰。

## 能把 Key 放到浏览器前端吗？

不能。浏览器里的任何 Secret 最终都可被用户或第三方脚本读取。前端应用应调用你自己的后端，由后端安全保存并使用 Key。

## 请求失败会不会扣费？

是否产生用量取决于请求是否已经到达并被上游实际处理。尤其是流式请求，收到部分输出后失败可能已产生费用。以控制台用量明细为准。

## 如何反馈故障？

提供发生时间、客户端版本、端点、模型、HTTP 状态码、脱敏错误体和 `X-Request-ID`。不要发送完整 Key 或对话隐私内容。
