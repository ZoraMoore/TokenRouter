# 云桥词元模型配置

帮助用户在自己的电脑上，通过 CC Switch 保存云桥词元供应商配置，让 Codex 使用当前 Key 可调用的 GPT 模型。每次更新都查询当前目录，模型 ID 随站点上架情况变化。

## 接入信息

| 项目 | 地址或取值 |
| --- | --- |
| 主站 | https://api.scienceedu.me |
| API 密钥 | https://api.scienceedu.me/keys |
| 模型广场 | https://api.scienceedu.me/models |
| 使用文档 | https://docs.scienceedu.me |
| Codex Base URL | `https://api.scienceedu.me/v1` |
| Codex 协议 | `responses` |
| 当前 Key 的模型目录 | `GET https://api.scienceedu.me/v1/models` |
| CC Switch | https://github.com/farion1231/cc-switch |

供应商名称可以使用“云桥词元 API”。已能使用的连接继续使用其 Key 和认证方式。用户指定其他域名时，核对站点文档或用户的端点来源后再发送凭据。

## 先确定运行位置和目标

从已有上下文、客户端配置和工具能力确认这些信息，缺失时集中询问：

- Codex 在 Windows、macOS、Linux、WSL 还是远程主机运行，CC Switch 管理的是哪个配置目录。
- 用户要首次接入、切换默认模型、添加模型菜单选项，还是排查某个错误。
- 云桥词元供应商是否已经存在，当前使用直连、路由接管还是聚合模式。
- 用户指定的完整模型 ID。用户说“最新”时，结合站点公告和当前 Key 的目录确定候选。

在执行环境属于服务器、容器或远程主机时，先核对它是否就是用户要配置的机器。用户电脑上的 CC Switch 不会因修改服务器的 `~/.codex` 而更新。

用户已要求配置或切换时，执行可用工具支持的操作。有桌面操作工具时使用 CC Switch 界面；工具无法操作该应用时，提供具体点击步骤和脱敏配置片段，并将结果标为“待用户在 CC Switch 保存”。浏览器工具只能操作网站时，不能据此声称已操作桌面应用。

## 查询模型

1. 在云桥词元 API 密钥页面找到用户要用的 Key，查看该 Key 的分组和“使用 Key”配置。首次接入时让用户在网站创建 Key，并在 CC Switch 的密钥输入框中填写。
2. 已配置的供应商，在 CC Switch 编辑页使用“获取模型”或“获取模型列表”。需要独立核对时，用同一个 Key 请求 `/v1/models`，读取 `data[].id`。认证为 `Authorization: Bearer` 加该 Key。
3. 模型 ID 按接口返回的完整字符串使用，包括斜杠、复合 Key 前缀或别名。显示名称、供应商品牌和上游模型名可能与请求 ID 不同。
4. 为 Codex 选择支持 Responses 的文本或代码模型。以网站“使用 Key”中的 Codex 选项、协议标记及实际调用为依据。模型目录包含图片等其他类型时，不能把它们当作 Codex 对话模型。
5. 用户指定的 ID 不在目录时，核对 Key、分组和站点公告。公开模型广场展示其他分组的模型，不代表此 Key 已获准使用。若站点明确说明某个新模型尚未列入目录，可按该说明做一次最小验证，记录例外来源。
6. “最新”无法从目录的排列顺序、名称排序或 `created` 时间可靠确定时，列出候选让用户选择。保留用户指定的型号，自动升级到另一档模型需要用户选择。

Key 在本地安全输入或从用户指定的供应商配置中读取，读取时在内存使用。输出仅展示“已配置”或掩码。含 Key 的配置、导入链接、备份和截图都按凭据文件处理。网站生成的“导入到 CCS”链接直接在用户本机打开；公开教程和回复使用占位符。

## 在 CC Switch 保存并启用

具体字段和两种认证方式见 [Codex 配置说明](references/codex.md)。按当前界面选择操作，不同版本的按钮名称可以不同。

### 首次接入

1. 从 [CC Switch Releases](https://github.com/farion1231/cc-switch/releases/latest) 获取适合用户系统的版本。已安装时直接使用。
2. 打开网站 API 密钥页面，在目标 Key 的“更多”菜单选择“导入到 CCS”，在导入窗口选择 Codex 和需要的模型，核对 Base URL 为 `https://api.scienceedu.me/v1`。
3. 导入入口不可用时，在 CC Switch 的 Codex 页添加自定义供应商，填写名称、Base URL、API Key 和查询到的模型 ID，选择 Responses 协议。
4. 保存后，在 Codex 页启用该供应商。导入成功与供应商已启用需要分别确认。

### 更新已有 GPT 模型

1. 记录当前供应商、默认模型、连接模式和待改字段。使用 CC Switch 的备份或导出功能保存本机备份，含凭据的备份放在用户私有目录。
2. 打开 Codex 页中云桥词元供应商的“编辑”，刷新可用模型。
3. 用户要更换默认模型时，修改“默认模型”或 TOML 顶层的 `model`。有“模型列表”的版本，根据界面提示设置默认项；部分版本以列表第一行为默认。已有其他模型继续留在列表中。
4. 用户只想增加菜单选项时，在模型列表添加目标 ID，默认模型继续指向当前选择。显示名称可以另填，实际请求模型使用查询结果。
5. 保存后确认当前启用的是这个供应商。直连模式检查 Codex 配置；路由或聚合模式同时检查 CC Switch 中的目标供应商及模型映射。接管时出现回环地址和代理占位凭据是正常情况，写入上游地址的位置是供应商编辑页。
6. 统一供应商生成的 Codex 配置，要检查父配置中的 Codex 模型设置。后续“同步”可能重新写入子配置；修改父配置的 Codex 部分并核对同步预览。其他应用的模型按用户选择处理。

每次编辑仅提交当前请求需要的字段。MCP、项目权限、登录态、其他供应商和其他模型的设置保持用户已有值。整份模板覆盖已有文件会删除这些内容。CC Switch 的数据库、内部设置文件和自动生成的模型缓存由应用管理，使用其界面或该版本公开支持的接口更新。

切换型号不自动推导上下文窗口、压缩阈值、思考等级、Fast 模式或 WebSocket 支持。这些能力按当前分组和模型文档核对，有明确需要再配置。

## 验证生效

- 重新打开供应商编辑页，确认保存的默认模型和模型列表。
- Codex CLI 退出后重新启动，Codex App 完全退出后启动，编辑器扩展重载窗口。使用新会话检查，已有会话可能继续使用先前选定的模型。
- 核对 Codex 当前模型和 provider。CLI 可用 `/status` 查看；配置存在 profile、项目级覆盖或启动参数时，按 [Codex 配置说明](references/codex.md) 检查实际生效层。
- 配置任务需要连通性验证时，用目标模型发一次“只回复 OK”的短请求。使用 CC Switch 的模型测试时，核对测试所选模型就是目标 ID。网站用量记录应显示该次请求的模型，若存在模型映射，再核对请求 ID 与映射目标。模型自述不作为身份验证依据。
- 独立验证 Responses API 时，按站点兼容要求使用 `store: false`、`stream: true` 和消息数组。检查流最终完成事件及输出；HTTP 200 或收到首个事件不能证明生成成功。这次请求会产生少量用量。

当前工具无法重启客户端或发起验证时，如实写明已保存、待重启或待实测。模型目录成功返回仅证明目录查询成功。

## 失败处理

遇到失败，依据 [Codex 配置说明中的排查表](references/codex.md#排查表) 定位。401、403 和持续出现的 429 应停止重复测试，先处理 Key、权限或额度。修正具体原因后再做一次验证。

用户要撤销时，通过 CC Switch 恢复本次修改的字段或切回先前供应商，并重新加载客户端。需要恢复整份备份时，先核对备份后是否发生其他修改，防止一并覆盖。

## 其他客户端

仅在用户使用 Claude Code 或 OpenCode 时读取 [其他客户端说明](references/other-clients.md)。GPT 型号名称不能用来推断客户端协议。

## 交付给用户

简洁说明当前客户端、供应商、模型 ID、实际修改位置和验证结果。需要用户操作时，列出剩余步骤。附本机备份位置或回退方法，隐去 Key。对“配置已保存”“客户端已加载”“实际请求成功”分别给出已有证据。
